# IntraBox 开源仓库

**定位**：说明源码托管方式（不是功能设计）。  
**读者**：贡献者、维护者与 AI 助手。

IntraBox 采用 **Gitee 主仓库 + GitHub 镜像** 的开源托管模式。日常版本管理只走 Gitee；GitHub 由 Gitee 仓库镜像推送同步，便于国际访问和 GitHub Actions。

| 角色 | 平台 | 地址 | 做什么 |
|------|------|------|--------|
| **主仓库** | [Gitee](https://gitee.com/xinyi6952/IntraBox) | https://gitee.com/xinyi6952/IntraBox | clone / pull / push、Issue、Pull Request、发版、日常协作 |
| **镜像** | [GitHub](https://github.com/xinyi6952/IntraBox) | https://github.com/xinyi6952/IntraBox | 只读镜像；同步后跑 `.github/workflows/build.yml` |

原则：

1. **只向 Gitee 推送。** 不要把 GitHub 当作日常 `origin`。  
2. Gitee 镜像方向必须是 **推送**（Gitee → GitHub）。不要改成「拉取」，否则会变成 GitHub 覆盖 Gitee。  
3. 贡献以 **Gitee 的 Issue / Pull Request** 为准。GitHub 上的 PR 不会作为主流程，镜像同步还可能覆盖未合并的 GitHub 侧改动。  
4. 本机远程约定：`origin` = Gitee，`github` = GitHub（仅镜像失败时补推）。

---

## 1. 日常操作

```text
git clone https://gitee.com/xinyi6952/IntraBox.git
git pull origin main
git push origin main
```

不要执行 `git push github`，除非确认 Gitee 镜像失败、需要临时补推。

已有本地仓若 `origin` 仍指向 GitHub，改为：

```bat
git remote rename origin github
git remote add origin https://gitee.com/xinyi6952/IntraBox.git
git fetch origin
git branch -u origin/main main
```

---

## 2. 贡献

1. Fork **Gitee** 主仓库，创建 `feature/xxx` 或 `fix/xxx` 分支。  
2. 提交说明见 [代码提交规范](代码提交规范.md)。  
3. `test.bat` 全绿后再向 Gitee 的 `main` 提 Pull Request。  
4. Issue 同样开在 Gitee：https://gitee.com/xinyi6952/IntraBox/issues  

更完整的环境与模块约定见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

---

## 3. 维护者：镜像

Gitee 仓库 → **管理** → **仓库镜像管理**：

- 方向：推送（Gitee → GitHub）  
- 镜像仓库：`xinyi6952/IntraBox`（`https://github.com/xinyi6952/IntraBox.git`）  
- 私人令牌：GitHub PAT（classic），勾选 `repo`；不是 Gitee 密码，也不是 GitHub 登录密码  

添加后可点一次「同步」确认。之后只推 Gitee，GitHub 应自动跟上（通常几十秒，偶发数分钟）。

同步后 GitHub Actions 仍会在镜像仓跑构建与 BOM 检查。
