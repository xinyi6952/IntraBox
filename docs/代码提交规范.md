# IntraBox 代码提交规范

**版本**：v1.0（2026-09-06）  
**定位**：写 git 提交说明与是否拆分提交的约定（不是功能设计）。  
**读者**：贡献者与 AI 助手。评审防回归见 [代码评审清单](代码评审清单.md)。

| 修订日期 | 说明 |
|----------|------|
| 2026-09-06 | 初版：多改动用无序列表、禁止 Agent 署名、默认一条提交 |

相关：[CONTRIBUTING](../CONTRIBUTING.md) · [AGENTS.md](../AGENTS.md) · [代码评审清单](代码评审清单.md) · [开源仓库](开源仓库.md)

---

## 1. 怎么用

| 项 | 约定 |
|----|------|
| **何时提交** | 仅在仓库主人明确要求「提交 / commit」时由助手执行；人可随时按本规范自己提交 |
| **默认条数** | **一条提交**覆盖当前要入库的全部改动。未说明「分多次 / 分阶段 / 拆成 N 个 commit」时，禁止拆成多条 |
| **语言** | 简体中文；写「为什么」，少堆文件名 |
| **产出** | 干净的 `git commit` 说明：无工具身份、无 Co-authored-by 等拖车行 |

**执行顺序（助手代提交时）**

1. `git status` / `git diff` / `git log` 看范围与既有语气。  
2. 未要求提交则停止。  
3. 按 §2、§4 写说明；多改动点用无序列表。  
4. 只暂存应入库的文件（勿加 `bin/`、`dist/`、密钥、用户数据）。  
5. 一次 `git commit`；成功后再 `git status` 核对。

## 2. 高发问题（先过脑）

| # | 模式 | 典型后果 | 自检一句 |
|---|------|----------|----------|
| C1 | **多改动写成一段或 1. 2. 3.** | 扫 log 看不清点 | 是否用 `-` 无序列表，每条一件事？ |
| C2 | **附带 Agent 身份** | log 被工具广告污染 | 有无 `Co-authored-by` / `Made-with` / 模型名？ |
| C3 | **未要求就拆 commit** | 一条需求碎成一串记录 | 用户是否说了分多次/分阶段？没有则合并为一条 |
| C4 | **只写「改了什么文件」** | 看不出动机 | 标题/列表是否在说原因或用户可感知结果？ |
| C5 | **把不该入库的文件打进去** | 仓库膨胀或泄密 | 有无 `dist/`、`bin/`、`.agents-local/`、数据目录？ |

## 3. P0 提交前检查

- [ ] 主人已明确要求提交（助手场景）
- [ ] 未要求拆分时，只有 **一条** 将创建的 commit
- [ ] 说明里没有工具身份（见 §4.2）
- [ ] 多个改动点已用 **无序列表**（见 §4.1）
- [ ] 暂存区没有构建产物、个人配置、密钥
- [ ] 含中文的源码仍带 UTF-8 BOM（若本次改了 `.cs`/`.xaml`）

## 4. 提交说明格式

### 4.1 正文结构

**只有一个改动点**：一行标题即可（可再跟一句补充）。不要为凑格式硬拆列表。

```text
账号备忘勾选加密后界面改为掩码，避免复制到空账号
```

**多个改动点**：第一行概括，空一行后用 `-` 无序列表（不要 `1.` `2.`，不要用顿号把几件事挤在一行）。

```text
完善账号备忘编辑与提交体验

- 勾选加密后账号密码显示掩码，取消勾选需验证查看密码
- 编辑页增加保存并关闭
- 行内删除改为再点一次确认
```

- 列表每条一句、平行、可独立理解。  
- 不要在列表里再写 `Co-authored-by` 或「由某某模型生成」。

### 4.2 禁止出现在提交中的内容

说明正文、正文以下的 trailer、以及 hook 自动加的广告，一律不要：

- `Co-authored-by:` / `Co-Authored-By:`（含 GitHub noreply、Anthropic、Cursor、OpenAI 等）
- `Made-with:`、`Generated by`、`Signed-off-by` 里的助手身份
- 模型或产品名：Claude、GPT、Codex、Cursor、Copilot、Fable 等当作作者
- 「作为 AI / 我是语言模型」类句子

提交作者保持仓库主人自己的 `user.name` / `user.email`。助手**不得** `git config` 写入工具身份，也不得用 `--trailer` 加上述行。

若 hook 自动注入了这类行：这次提交作废重写（不要 `--amend` 到已推送的历史，除非主人明确要求）。

### 4.3 何时才能多条提交

仅当主人明确说了例如：

- 分多次提交 / 拆成多个 commit  
- 分阶段提交（先修 bug 再提功能）  
- 按模块或按文件分别提交  

此时才拆；每条仍遵守 §4.1、§4.2。未说明则 **一条提交包含全部约定入库的改动**。

## 5. 触发表

| 触发 | 必做 |
|------|------|
| 用户说「提交」「commit」「写 commit」 | 本清单全文：默认一条、说明格式、禁止工具身份 |
| 工作区有多类改动（功能+文档+测试） | §4.1 无序列表；仍一条 commit（除非用户要求拆） |
| 准备 `git commit` | §3 P0；检查暂存区与 trailer |
| 用户说分多次/分阶段 | 才拆 commit；每条单独符合 §4 |

**红线**

1. 未要求拆分时禁止拆成多条提交。  
2. 提交说明与 trailer 禁止任何 Agent / 模型 / 编辑器身份。  
3. 多个改动点必须用无序列表，不用编号列表冒充条理。  
4. 未要求时不 commit、不 push、不改 git config。

## 6. 反例

```text
# 差：工具身份
fix vault encrypt
Co-authored-by: Claude Fable 5 <noreply@anthropic.com>
Co-authored-by: xinyi6952 <xinyi6952@users.noreply.github.com>
```

```text
# 差：多件事挤一行、又拆了好几个无意义 commit
改了 VaultEditorPanel
（另两条：改文档 / 改测试）
```

```text
# 好：一条提交，多点用无序列表
完善账号备忘

- 加密行界面不再显示明文
- 复制全部与导出导入使用同一格式
```
